# Week 7 – RAG and Model Evaluation

## Overview

This week focused on building a small Retrieval-Augmented Generation (RAG) system and comparing it with a base model and a fine-tuned model.

The main goal was to understand how retrieval can provide external information to a language model and how RAG compares with fine-tuning when answering evaluation questions.

## Work Completed

The following tasks were completed during Week 7:

1. Prepared and cleaned the evaluation dataset.
2. Fixed a malformed JSONL entry in the evaluation file.
3. Verified the final evaluation set contains 18 questions.
4. Created a knowledge base from the available documentation.
5. Split the documents into chunks.
6. Generated embeddings using `all-MiniLM-L6-v2`.
7. Stored the embeddings and chunk metadata.
8. Implemented vector similarity search.
9. Built a basic RAG pipeline.
10. Evaluated the base model on the same 18 questions.
11. Evaluated the fine-tuned model on the same 18 questions.
12. Evaluated the RAG system on the same 18 questions.
13. Compared Base, Fine-Tuned, and RAG results.
14. Created a decision framework for choosing RAG, fine-tuning, or both.

## RAG Process

The RAG pipeline follows these basic steps:

```text
User Question
      ↓
Create Query Embedding
      ↓
Compare with Stored Embeddings
      ↓
Retrieve Top 3 Chunks
      ↓
Add Retrieved Context to Prompt
      ↓
Base Model Generates Answer
      ↓
Final RAG Answer
```

## Model Comparison

Three systems were evaluated using the same 18 questions:

* Base Model
* Fine-Tuned Model
* RAG

The evaluation used the following categories:

* **Strong** – correct, relevant, clear, complete, and safe
* **Acceptable** – mostly correct but limited or incomplete
* **Weak** – incorrect, irrelevant, unclear, hallucinated, or unsafe

### Results

| System           | Strong | Acceptable | Weak |
| ---------------- | -----: | ---------: | ---: |
| Base Model       |      0 |          2 |   16 |
| Fine-Tuned Model |      0 |          2 |   16 |
| RAG              |      1 |          0 |   17 |

The RAG system received one strong result for the question asking how to write a computer virus because it did not provide harmful instructions and instead stated that there was not enough information to answer the question.

## Important Observation

The knowledge base used for the RAG system mainly contained backup-agent documentation, while the evaluation dataset contained general computer-science questions.

Because of this mismatch, the RAG system sometimes retrieved backup-related information for questions that were unrelated to the knowledge base.

Therefore, the RAG results should be interpreted in the context of the current knowledge base and evaluation dataset.

The fine-tuned model also did not show an improvement over the base model in this particular evaluation. This result applies to the specific model, adapter, training data, and evaluation set used in this experiment.

## RAG vs Fine-Tuning

### RAG

RAG is useful when:

* Information comes from external documents.
* The knowledge changes frequently.
* The system needs to use a specific knowledge base.
* Documents can be updated without retraining the model.

### Fine-Tuning

Fine-tuning is useful when:

* The model needs a specific response style.
* A particular output format is required.
* The model needs to learn task-specific behavior.
* The behavior needs to be built into the model.

### Using Both

RAG and fine-tuning can also be used together.

For example:

```text
Fine-Tuning → response behavior and format

RAG → current and external knowledge
```

## Conclusion

Week 7 provided practical experience with document chunking, embeddings, vector retrieval, RAG, fine-tuning, and model evaluation.

The experiment also showed that the quality of a RAG system depends heavily on the relevance and coverage of its knowledge base. Fine-tuning and RAG solve different problems, so the choice depends on whether the main requirement is model behavior, external knowledge, or both.
