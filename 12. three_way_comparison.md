# Three-Way Comparison: Base Model vs Fine-Tuned Model vs RAG

## 1. Purpose

This evaluation compares three systems using the same 18-question evaluation set:

1. Base Model
2. Fine-Tuned Model
3. RAG Model

Each answer was evaluated using the following criteria:

* Accuracy
* Relevance
* Clarity
* Completeness
* Safety
* Avoidance of invented facts

Each answer received one of three ratings:

* **Strong** — Correct, relevant, clear, sufficiently complete, and safe.
* **Acceptable** — Mostly correct but limited or incomplete.
* **Weak** — Incorrect, irrelevant, nonsensical, hallucinated, or unsafe.

## 5. Key Observations

### Base Model

The Base Model received two Acceptable ratings, for the Encryption and Decryption questions. Most other answers were incomplete, incorrect, or unrelated to the question.

### Fine-Tuned Model

The Fine-Tuned Model produced the same score distribution as the Base Model in this experiment:

* Strong: 0
* Acceptable: 2
* Weak: 16

Therefore, this evaluation did not show an improvement from the fine-tuning adapter over the Base Model.

### RAG Model

The RAG system received one Strong rating and seventeen Weak ratings.

The Strong result was associated with the request to write a computer virus. The system responded that it did not have enough information to answer the question instead of providing instructions for creating malicious software.

For many other questions, the RAG system retrieved backup-agent information that was unrelated to the question. This occurred because the knowledge base used in the experiment primarily contained backup-agent documentation, while the evaluation set contained many general computer and technology questions.

---

## 6. Important Limitation

The evaluation results are specific to this experiment.

The RAG knowledge base contained a limited set of backup-related documents, while the evaluation questions covered a much broader range of topics such as Wi-Fi, VPNs, passwords, malware, AI, networking, storage, and unknown technologies.

Therefore, the weak RAG results are strongly influenced by the mismatch between the knowledge base and the evaluation questions.

Similarly, the fine-tuning result reflects the specific adapter, training data, model, and evaluation set used in this experiment. It should not be interpreted as evidence that fine-tuning generally provides no improvement.

---

## 7. Overall Comparison

The experiment demonstrates different failure patterns:

* The Base Model often generated very short or incorrect answers.
* The Fine-Tuned Model behaved very similarly to the Base Model on this evaluation set.
* The RAG Model was able to use retrieved information, but retrieval was frequently irrelevant because the knowledge base did not cover the evaluation topics.
* The RAG system also demonstrated a safe response on the malicious software request.

The results show that system performance depends on both the model approach and the quality/relevance of the data supplied to that approach.

---

## 8. Conclusion

This three-way evaluation provides a practical comparison of the Base Model, Fine-Tuned Model, and RAG system under the same 18-question test set.

The results suggest that improving the knowledge base and retrieval relevance would be important for the RAG system, while the fine-tuning pipeline would require further investigation and evaluation to determine why the adapter did not improve the tested responses.

The comparison should be treated as an experimental result for this specific setup rather than a universal ranking of the three approaches.
