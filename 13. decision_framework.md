# Decision Framework: RAG vs Fine-Tuning vs Both

## 1. Purpose

This document provides a practical framework for deciding between Retrieval-Augmented Generation (RAG), Fine-Tuning, or a combination of both.

The decision should depend on the type of information the system needs, how often that information changes, the required response behavior, and the available training and maintenance resources.

---

## 2. RAG

### How it works

RAG retrieves relevant information from an external knowledge base and provides that information to the language model as context before generating an answer.

### When to use RAG

RAG is useful when:

* The information comes from documents or a knowledge base.
* Information may change over time.
* New documents should be added without retraining the model.
* The system needs to provide answers based on specific source material.
* Reducing unsupported answers is important.

### Practical advantage

The main advantage of RAG is that the knowledge base can be updated independently of model training. For example, if a troubleshooting document changes, the updated document can be indexed and used by the RAG system without retraining the language model.

### Practical limitation

RAG depends heavily on retrieval quality and knowledge-base coverage. If the required information is not present in the knowledge base, retrieval may return irrelevant information.

This was observed in this evaluation. The knowledge base mainly contained backup-agent documentation, while many evaluation questions were about general computer concepts. As a result, the RAG system frequently retrieved backup-related information for unrelated questions.

---

## 3. Fine-Tuning

### How it works

Fine-tuning changes the model's learned behavior by training it on a task-specific dataset.

### When to use Fine-Tuning

Fine-tuning is useful when:

* The desired response style needs to be learned.
* A consistent task-specific behavior is required.
* The model needs to follow a particular format.
* The training examples represent the behavior that should be reproduced.

### Practical advantage

Fine-tuning can teach a model how to respond in a particular style or format without requiring the relevant information to be retrieved for every query.

### Practical limitation

Fine-tuning is not an ideal mechanism for frequently changing factual information. When the underlying facts change, the model may need additional training.

The evaluation also showed that the fine-tuned model did not produce a measurable improvement over the base model on this particular evaluation set. Both systems received:

* Strong: 0
* Acceptable: 2
* Weak: 16

This indicates that the adapter used in this experiment did not improve the evaluated answers.

---

## 4. Using Both RAG and Fine-Tuning

RAG and Fine-Tuning solve different problems, so they can be combined.

A combined system can use:

* **Fine-Tuning** for response behavior, style, formatting, or task-specific patterns.
* **RAG** for current, external, or document-based information.

### Example

For a technical support assistant:

1. Fine-Tuning can teach the model how to structure troubleshooting responses.
2. RAG can retrieve the latest troubleshooting documentation.
3. The model can generate the final answer using the retrieved documentation while following the desired response format.

This approach separates behavior from knowledge:

**Fine-Tuning → How the model responds**

**RAG → What information the model uses**

---

## 5. Practical Decision Framework

| Requirement                                                      | Recommended Approach |
| ---------------------------------------------------------------- | -------------------- |
| Frequently changing documentation                                | RAG                  |
| Large external knowledge base                                    | RAG                  |
| Need answers grounded in documents                               | RAG                  |
| Specific response style or format                                | Fine-Tuning          |
| Repeated task-specific behavior                                  | Fine-Tuning          |
| Current knowledge + specialized response behavior                | Both                 |
| Limited training resources                                       | Start with RAG       |
| Knowledge changes frequently                                     | Prefer RAG           |
| Behavior needs customization                                     | Consider Fine-Tuning |
| Both knowledge grounding and behavior customization are required | Both                 |

---

## 6. Decision Process

The following questions can be used when selecting an approach:

### Question 1: Does the system need information from external documents?

If yes, RAG should be considered.

### Question 2: Does the information change frequently?

If yes, RAG is generally more practical because documents can be updated without retraining the model.

### Question 3: Does the model need a specific response behavior or format?

If yes, Fine-Tuning may be useful.

### Question 4: Are both current external knowledge and specialized behavior required?

If yes, a combined RAG + Fine-Tuning architecture can be considered.

### Question 5: Is the knowledge base relevant to the questions?

This is especially important for RAG. Retrieval quality depends on the coverage and quality of the knowledge base.

---

## 7. Findings From This Experiment

This experiment compared a Base Model, Fine-Tuned Model, and RAG system using the same 18-question evaluation set.

### Base Model

* Strong: 0
* Acceptable: 2
* Weak: 16

### Fine-Tuned Model

* Strong: 0
* Acceptable: 2
* Weak: 16

### RAG

* Strong: 1
* Acceptable: 0
* Weak: 17

The RAG system produced a strong safe response for the computer-virus request by stating that it did not have enough information to answer the question. However, it frequently returned backup-related information for general questions because the knowledge base was focused on backup-agent documentation.

The Base and Fine-Tuned models produced the same score distribution in this experiment. Therefore, the experiment did not demonstrate an improvement from the fine-tuning adapter on this evaluation set.

These results should be interpreted as observations from this particular dataset and setup rather than as a general statement that one architecture is always better.

---

## 8. Final Practical Guidance

A practical development strategy is:

1. Start with a good base model.
2. Build a relevant and well-structured knowledge base.
3. Add RAG when answers need external or frequently updated information.
4. Evaluate retrieval quality before changing the model.
5. Use Fine-Tuning when response behavior, formatting, or task-specific behavior needs customization.
6. Consider combining Fine-Tuning and RAG when both specialized behavior and external knowledge are required.
7. Re-evaluate the system whenever the knowledge base, model, adapter, or evaluation dataset changes.

The most important factor is not simply choosing RAG or Fine-Tuning. The approach should match the actual problem: **RAG is primarily a knowledge-grounding mechanism, while Fine-Tuning is primarily a behavior/task-adaptation mechanism.**
